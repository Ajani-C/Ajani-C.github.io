      Find the scanner
      
              
      A SYN scan sends connection requests to many ports and walks away. Show only packets that start a connection and have not been acknowledged.
      
              tcp.flags.syn == 1 && tcp.flags.ack == 0
              
              
      One address, 192.168.1.66, sends every probe from the same source port to dozens of different ports on 192.168.1.50. A normal client opens a few connections to a few ports.
      
            
      
            
      
              
      Which ports are open?
      
              
      Open ports answer a SYN with SYN/ACK. Closed ports answer with a reset. Show only the SYN/ACK replies sent back to the scanner.
      
              tcp.flags.syn == 1 && tcp.flags.ack == 1 && ip.dst == 192.168.1.66
              
              
      Ports 22, 80 and 3306 answered: SSH, a web server and MySQL on one host. The scanner then sent a reset to each one, so the handshake never completed. That is a half-open scan.
      
            
      
            
      
              
      Spot a credential leak
      
              
      Plain HTTP sends everything as readable text. Search the capture for the word password.
      
              frame contains "password"
              
              
      A login form sent a username and password over HTTP on port 80. Anyone on the network path could read it. HTTPS would have encrypted it, like the session on port 443.
      
            
      
          
      
        
      
      
      

      
      
        
      
          
      
            
      
              
              
            
      
            
            
      
            
      
            
      
            
      
          
      
          
      
            
      Dictionary attack, running on your input
      
            
      Your password is hashed with SHA-256, then the page tries about 3,000 common words with the usual tweaks until one produces the same hash. This is the idea behind Hashcat and John the Ripper.
      
            
      SHA-256 of your password
      
            
      
            
      
            
      
            
      What helps
      
            
      Use 14 or more characters, or a passphrase of four or more unrelated words. Use a different password on every site, with a password manager. Sites should store passwords with a slow hash such as bcrypt or Argon2, not a fast one.

      SIEM deployment and attack simulation (Splunk on VM)

      Run these rules live
      
        
      
        
      
          
          
      For this project, I deployed a Splunk SIEM in a virtual machine environment and configured forwarder agents to collect logs from different systems. Once the SIEM was operational, I simulated attacks (such as brute force login attempts and port scans) to generate realistic security events.
      
          
          
      I wrote detection queries (in Splunk SPL) to analyze the collected logs, detect malicious activity, and create custom dashboards to visualize security alerts.
      

          
      
            
      Brute force login attempts: failed logins by the same user and address
      

      index=security sourcetype=auth
action="failure"
| stats count by src, user
| where count > 10
      
          
      
          
      
            
      Successful login after failures: a possible brute force success
      

      index=security sourcetype=auth
| transaction user maxspan=5m
| search failure failure failure success
      
          
      
          
      
            
      Port scanning activity: many ports hit by the same address
      

      index=network sourcetype=firewall
| stats dc(dest_port) as unique_ports by src_ip
| where unique_ports > 20
      
          
      

          
      This project demonstrated how SIEM solutions help security analysts monitor environments, identify threats, and respond to incidents in real time. It also strengthened my skills in log collection, query writing, and attack detection.
